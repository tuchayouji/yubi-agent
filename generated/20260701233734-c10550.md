## 一、LangChain 概述：为什么需要这个框架？

刚写完调用 GPT-4 的接口代码，转头老板说要把模型换成通义千问，结果你发现参数名、请求格式全得重写，之前写的业务逻辑要推倒一半？想做 RAG 文档问答，光是把大模型、向量数据库、文本分割器捏合到一起就花了三天，改个 Prompt 还要扒好几百行代码？

如果你也经历过这些 LLM 应用开发的糟心时刻，LangChain 就是为你量身打造的解决方案。

作为当前主流的 LLM 应用编排框架，LangChain 的定位从来不是大模型本身，而是 AI 应用的"连接器"和"脚手架"：它把不同厂商的大模型 API、Prompt 管理、文档处理、向量检索等常用能力全部封装成标准化接口，你不用再逐个适配不同模型的独特调用规则，只需要专注实现自己的业务逻辑就行。

### 核心价值与痛点解决

LangChain 的核心价值是解决了 LLM 开发的两大核心痛点：

**1. 消除多模型集成的复杂度**
不同厂商的 API 差异（参数名、认证方式、响应格式）被抽象为统一的接口。后续换模型只需要改一行配置（如将 `ChatOpenAI` 替换为 `ChatOllama` 或通义千问的对应类），原有业务代码完全不用动。

**2. 模块化的链路构建方式**
不管是简单的单轮对话，还是多步骤的复杂工作流，都可以通过 LCEL（LangChain Expression Language）像拼乐高一样把各个组件串联起来。这种声明式语法让代码可读性、可维护性都远高于零散编写的业务逻辑。

### 应用场景覆盖

从入门级的智能聊天机器人、Prompt 调试工具，到进阶的 RAG 文档问答、企业知识库系统，再到高阶的 Agent 工具调用、多步骤自动化工作流，LangChain 都能覆盖。不管是个人开发者做小工具练手，还是企业团队落地业务级 AI 应用，它都能把开发周期从几周压缩到几天，大幅降低 LLM 应用的开发门槛。

### 开发生态

LangChain 还提供了完整的开发生态：
- **LangSmith**：调试与监控平台，用于追踪链路的运行状态和性能

这些工具进一步降低了从原型到生产的门槛。

### 本节小结

简单来说，LangChain 就是 LLM 应用的"基础设施层"，帮你把重复的适配、链路拼接工作做完，你只需要把精力放在业务逻辑本身，就能快速落地可用的 AI 产品。

## 二、LangChain 核心语法与实战

### 2.1 LCEL（LangChain Expression Language）

LCEL 是 LangChain 0.1 版本后主推的核心语法，它借鉴了 Unix 管道的设计哲学，让 AI 应用构建变得直观而优雅。LCEL 的核心是 **Runnable 协议**——所有组件（Prompt、模型、输出解析器、检索器等）都实现了统一的 `invoke`、`batch`、`stream`、`ainvoke` 接口，因此可以使用 `|` 操作符将它们串联成管道。

你可以使用 `|` 操作符将 Prompt、模型和输出解析器串联起来，数据流会依次经过每个节点。这种声明式语法不仅代码简洁，还原生支持流式输出、异步调用和批处理，非常适合构建生产级应用。

#### 环境准备

在开始之前，请确保安装以下依赖：

```bash
pip install langchain langchain-openai langchain-community chromadb fastapi uvicorn
```

同时配置环境变量：

```bash
export OPENAI_API_KEY="your-api-key"
# 或在代码中设置
import os
os.environ["OPENAI_API_KEY"] = "your-api-key"
```

#### 最小闭环示例

一个最小闭环由三要素构成：`ChatPromptTemplate` 定义提示词结构，`ChatOpenAI`（或其他 LLM）执行推理，`StrOutputParser` 则将输出转换为纯字符串。

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# 定义 Chain：提示词模板 | 模型调用 | 输出解析
chain = (
    ChatPromptTemplate.from_template("用一句话解释{topic}") 
    | ChatOpenAI(model="gpt-4o-mini", temperature=0.7) 
    | StrOutputParser()
)

# 同步调用：处理单次输入
result = chain.invoke({"topic": "LangChain"})
print(result)

# 批量调用：同时处理多个输入
batch_results = chain.batch([
    {"topic": "LangChain"}, 
    {"topic": "RAG"}
])
print(batch_results)

# 流式调用：逐 token 输出，适合实时交互
for chunk in chain.stream({"topic": "LangChain"}):
    print(chunk, end="", flush=True)

# 异步调用：适用于高并发场景
import asyncio
async def async_invoke():
    result = await chain.ainvoke({"topic": "LangChain"})
    print(result)

asyncio.run(async_invoke())
```

### 2.2 提示词工程与上下文管理

#### 变量预填与部分填充

在提示词工程方面，`ChatPromptTemplate` 提供了 `.partial()` 方法，允许你预填系统角色等固定变量，避免重复传入。

```python
from langchain_core.prompts import ChatPromptTemplate

# 预填系统角色
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个专业的{role}，擅长{skill}"),
    ("human", "{input}")
]).partial(role="Python编程助手", skill="代码优化和算法设计")

# 后续只需传入变化的 input
chain = prompt | ChatOpenAI() | StrOutputParser()
print(chain.invoke({"input": "如何优化这段代码？"}))
```

#### 多轮对话与历史管理

多轮对话通过 `HumanMessage`、`AIMessage` 和 `SystemMessage` 组织消息历史，LangChain 会自动维护上下文。

```python
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

# 多轮对话示例
messages = [
    SystemMessage(content="你是一个专业的Python编程助手"),
    HumanMessage(content="如何用Python读取CSV文件？"),
    AIMessage(content="可以使用pandas库：import pandas as pd; df = pd.read_csv('file.csv')"),
    HumanMessage(content="那如何筛选特定列？")
]

# 将消息列表传递给模型
prompt = ChatPromptTemplate.from_messages(messages)
chain = prompt | ChatOpenAI() | StrOutputParser()
response = chain.invoke({})
print(response)
```

#### 滑动窗口与上下文截断

随着对话变长，历史记录会消耗大量 Token。你可以启用滑动窗口机制：按消息数量（如保留最近 10 轮）或 Token 数量（如保留最近 2000 个 Token）进行截断，在保留关键上下文和控制成本之间取得平衡。

```python
from langchain_core.messages import trim_messages

# 按消息数量截断，保留最近 10 轮对话（20条消息，每轮包含human和ai）
trimmer = trim_messages(
    max_tokens=10,  # 保留最近10条消息
    strategy="last",
    token_counter=ChatOpenAI(model="gpt-4o-mini"),
    include_system=True
)

# 在链中使用
chain = (
    {"messages": trimmer | RunnablePassthrough()}
    | ChatPromptTemplate.from_messages([
        ("system", "你是一个有帮助的助手"),
        ("placeholder", "{messages}")
    ])
    | ChatOpenAI()
    | StrOutputParser()
)
```

此外，LangChain 还提供了 `MessagesPlaceholder` 变量来动态插入历史消息，便于在应用中灵活管理对话状态。

```python
from langchain_core.prompts import MessagesPlaceholder

# 使用 MessagesPlaceholder 动态插入历史
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个有帮助的助手"),
    MessagesPlaceholder(variable_name="history"),
    ("human", "{input}")
])

# 调用时传入 history 列表
chain = prompt | ChatOpenAI() | StrOutputParser()
chain.invoke({
    "history": [
        HumanMessage(content="你好"),
        AIMessage(content="你好！有什么我可以帮助你的吗？")
    ],
    "input": "之前说了什么？"
})
```

### 2.3 文档处理与向量化

#### 文档加载与分割

文档处理是 RAG 的基础。你可以使用 LangChain 的文档加载器读取 PDF、Word 等格式文件，随后通过文本分割器（如 `RecursiveCharacterTextSplitter`）将长文本切分为语义完整的块。

```python
from langchain_community.document_loaders import PyPDFLoader, TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

# 加载文档（支持 PDF、Word、TXT 等多种格式）
loader = PyPDFLoader("论文.pdf")
documents = loader.load()

# 文本分割
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每个块约500字符
    chunk_overlap=50,      # 块之间重叠50字符，保持上下文连贯
    separators=["\n\n", "\n", "。", "！", "？", " ", ""]  # 按段落优先分割
)
chunks = text_splitter.split_documents(documents)
print(f"共分割为 {len(chunks)} 个文本块")
```

关键参数说明：
- **chunk_size**（建议 500–1000 tokens）：块的大小，需要平衡上下文完整性和检索精度
- **chunk_overlap**（建议 10–20%）：块之间的重叠字符数，防止关键信息被切断

#### 向量化与持久化

处理后的文本块通过 Embedding 模型转换为向量，存入 Chroma 或 FAISS 等向量数据库。这些数据库能高效计算语义相似度，快速召回相关文档片段。

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

# 向量化并存储
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"  # 持久化到本地目录
)

# 后续加载已有向量库
# vectorstore = Chroma(
#     persist_directory="./chroma_db",
#     embedding_function=embeddings
# )
```

### 2.4 RAG（检索增强生成）实战

RAG 让模型基于检索结果回答问题。典型流程是：用户提问 → 向量库检索相关文档 → 构建上下文 Prompt → LLM 生成答案。

```python
from langchain_core.runnables import RunnablePassthrough

# 初始化检索器
retriever = vectorstore.as_retriever(
    search_type="similarity",  # 相似度检索
    search_kwargs={"k": 3}     # 返回前3个最相关的文档块
)

# 定义格式化函数，将检索到的文档拼接为字符串
def format_docs(docs):
    return "\n\n".join([doc.page_content for doc in docs])

# 构建 RAG 链路
rag_chain = (
    {
        "context": retriever | format_docs,  # 检索并格式化文档
        "question": RunnablePassthrough()      # 直接传递用户问题
    }
    | ChatPromptTemplate.from_template("根据以下上下文回答问题：\n\n上下文：{context}\n\n问题：{question}\n\n回答：")
    | ChatOpenAI(model="gpt-4o-mini", temperature=0)
    | StrOutputParser()
)

# 执行查询
answer = rag_chain.invoke("LangChain的核心组件有哪些？")
print(answer)
```

其中 `RunnablePassthrough` 用于直接将用户输入传递给下游的 Prompt 模板，实现了检索结果与原始问题的并行输入。

#### 检索策略优化

`search_type` 还支持 `"mmr"`（最大边际相关性，Maximal Marginal Relevance），以平衡相关性和多样性，避免检索结果过于相似。

```python
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 3,           # 返回文档数量
        "fetch_k": 10,     # 先召回10个候选，再从中挑选3个
        "lambda_mult": 0.5 # 相关性权重，0-1之间，越小多样性越高
    }
)
```

### 2.5 长文本总结策略

当面对长文本总结时，`load_summarize_chain` 提供了三种策略：

| 策略 | 适用场景 | 特点 |
|------|---------|------|
| `stuff` | 短文本（在上下文窗口内） | 简单直接，但受限于上下文长度 |
| `map_reduce` | 长文本 | 先分块总结再汇总，并行度高但可能丢失细节 |
| `refine` | 长文本 | 迭代优化，质量最高但速度最慢 |

```python
from langchain.chains.summarize import load_summarize_chain

# 加载长文本（已分割的文档）
documents = text_splitter.split_documents(loader.load())

# 使用 map_reduce 策略总结
chain = load_summarize_chain(
    ChatOpenAI(model="gpt-4o-mini"), 
    chain_type="map_reduce",
    verbose=True
)

# 执行总结
summary = chain.invoke(documents)
print(summary["output_text"])

# 也可以使用 stuff 策略（适合短文本）
# chain = load_summarize_chain(llm, chain_type="stuff")
```

### 2.6 服务化部署与本地模型

#### FastAPI 服务化

你可以使用 FastAPI 将 Chain 封装为 REST 接口，实现 HTTP 服务。注意在生产环境中应使用异步调用以避免阻塞事件循环。

```python
from fastapi import FastAPI
from pydantic import BaseModel
import asyncio

app = FastAPI()

# 定义请求模型
class QuestionRequest(BaseModel):
    question: str

# 异步包装函数（避免阻塞事件循环）
async def get_answer(question: str) -> str:
    loop = asyncio.get_event_loop()
    return await loop.run_in_executor(None, rag_chain.invoke, question)

@app.post("/qa")
async def question_answering(request: QuestionRequest):
    answer = await get_answer(request.question)
    return {"answer": answer}

# 启动服务：uvicorn main:app --reload
```

#### 本地模型接入

对于本地部署，Ollama 提供了简单的模型管理。新版 LangChain 推荐使用 `langchain_ollama` 包（或 `langchain_community.llms.Ollama`），通过 `ChatOllama` 可接入 Llama 3、Mistral 等开源模型，无需 OpenAI API，实现低延迟私有化部署。

```python
from langchain_ollama import ChatOllama

# 使用本地 Ollama 模型（确保已运行 ollama run llama3）
ollama_llm = ChatOllama(model="llama3")
local_chain = (
    ChatPromptTemplate.from_template("你好，请介绍一下你自己") 
    | ollama_llm 
    | StrOutputParser()
)
print(local_chain.invoke({}))
```

## 三、总结与学习路径

LangChain 通过 LCEL 将复杂的 LLM 应用开发抽象为优雅的管道式语法。掌握从 Prompt 模板到 RAG 应用的完整流程，你就能快速构建可维护、可扩展的 AI 系统。无论是简单的对话机器人还是复杂的文档问答，LangChain 都提供了标准化的解决方案，让你专注于业务逻辑而非底层集成。

### 核心要点回顾

到这里，我们已经把 LangChain 最核心的基础能力过了一遍：

1. **LCEL 管道语法**：用 `|` 操作符快速拼接组件，实现声明式 AI 应用构建
2. **提示词模板**：通过 `ChatPromptTemplate` 管理 Prompt，支持多轮对话和变量预填
3. **上下文管理**：使用 `MessagesPlaceholder` 和滑动窗口控制对话历史
4. **文档处理流程**：加载 → 分割 → 向量化 → 存储，构建 RAG 知识库
5. **RAG 检索生成**：结合检索器和 LLM，实现基于知识的问答
6. **服务化部署**：通过 FastAPI 和 LangServe 将应用部署为生产服务

LangChain 的核心思路就是"把 LLM 应用开发中重复的通用逻辑封装好，让你只需要关注业务本身的组合逻辑"。

### 学习建议

如果你刚上手，完全不用急着啃所有高级特性，建议按以下路径进阶：

1. **先跑通最小闭环**：把 LCEL 的最小闭环（提示词模板 → 模型调用 → 输出解析）跑通，理解 Runnable 协议的基本概念
2. **构建第一个 RAG Demo**：踩一遍加载文档、向量化、检索生成的完整流程
3. **探索服务化部署**：将 Demo 封装为 API，体验从原型到服务的完整链路
4. **深入高级特性**：根据实际需求探索自定义 Chain、Agent 工作流、LangSmith 调试等

后续你可以根据需求继续探索自定义 Chain、对接本地开源模型、甚至是搭建更复杂的 Agent 工作流。LangChain 生态里的 LangSmith 调试工具、LangServe 部署框架也能帮你大幅降低开发调试的成本。

毕竟现在 LLM 应用开发的试错成本已经足够低，用 LangChain 搭个能用的最小 Demo 可能只需要十几行代码，剩下的就是结合实际业务场景打磨细节了。

1. **官方文档与教程**：LangChain 官方文档（python.langchain.com）提供了最权威的 API 参考和快速入门指南，其中 LCEL 部分的内容尤其值得精读。
